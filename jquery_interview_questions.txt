TOP JQUERY INTERVIEW QUESTIONS AND ANSWERS
===========================================

CORE 5
------

1. What is jQuery and why was it used?

jQuery is a JavaScript library (2006) that wraps the DOM in a consistent API:
$(selector) returns a jQuery object wrapping matched elements, with chainable
methods for manipulation, events, animation, and AJAX.

Why it mattered: pre-2015 browsers had wildly inconsistent DOM/event APIs
(IE's attachEvent vs addEventListener, inconsistent getComputedStyle, no
querySelectorAll in old IE, XHR quirks). jQuery abstracted all of that behind
one API. Modern browsers have since standardized most of this
(querySelectorAll, fetch, classList, addEventListener everywhere), which is
why jQuery usage has declined -- but it's still common in legacy codebases
and WordPress.

Example:
    $('.btn').on('click', function() { $(this).toggleClass('active'); });


2. $(document).ready() vs window.onload

- $(document).ready(fn) fires as soon as the DOM tree is fully parsed --
  before images, iframes, and stylesheets finish loading.
- window.onload = fn fires only after ALL resources (images, CSS, subframes)
  have loaded.

Practically, .ready() lets you start binding events/manipulating the DOM
sooner. Shorthand: $(function(){...}) is equivalent to
$(document).ready(function(){...}). Native equivalent today:
DOMContentLoaded vs load events.

Example:
    $(document).ready(function() { console.log('DOM ready'); });
    $(function() { console.log('same thing, shorthand'); });
    window.onload = function() { console.log('everything loaded'); };


3. Event delegation -- .on() vs .bind()/.live()/.delegate()

- .bind(event, handler) -- attaches directly to matched elements at call
  time. Doesn't work for elements added later.
- .live(event, handler) (deprecated, removed in jQuery 1.9) -- attached to
  document, worked for future elements, but was slow (every event bubbled
  all the way up and got re-matched).
- .delegate(selector, event, handler) -- attach to a specific ancestor,
  filtering by a child selector. More efficient than .live().
- .on(event, selector, handler) -- the modern unified API. Called on a
  parent with a selector argument, it delegates: the event bubbles to the
  parent, and jQuery checks if event.target matches the selector.

Example:
    // Handles rows added to the table after page load
    $('#table-body').on('click', 'tr', function() {
      $(this).toggleClass('selected');
    });

Why it matters in interviews: shows you understand event bubbling and the
performance cost of binding hundreds of individual handlers vs. one
delegated handler.


4. .each() vs .map()

- .each(fn) -- iterates over the jQuery collection purely for side effects;
  returns the ORIGINAL jQuery object so you can keep chaining.
- .map(fn) -- iterates and COLLECTS RETURN VALUES into a new jQuery object
  (flattening arrays returned by the callback).

Example:
    $('li').each(function(i, el) {
      console.log(i, el.textContent); // side effect only
    });

    var texts = $('li').map(function() {
      return $(this).text(); // collects results
    }).get(); // .get() converts to a plain array


5. Selectors -- Sizzle engine vs querySelectorAll

jQuery selectors use the Sizzle engine, supporting full CSS3 selectors plus
jQuery-specific extensions (:visible, :hidden, :eq(n), :contains()) that
aren't valid CSS and can't be passed to native querySelectorAll. jQuery
also gives IMPLICIT ITERATION -- calling a method on a multi-element
selection applies it to all matched elements without an explicit loop --
whereas querySelectorAll returns a static NodeList you must loop over
manually.

Example:
    $('div:visible').hide();                    // jQuery extension selector
    document.querySelectorAll('div:visible');    // throws -- invalid CSS


FOLLOW-UPS WORTH KNOWING
------------------------

6. $.ajax() vs fetch()

$.ajax() returns a jQuery Deferred/Promise-like object (.done(), .fail(),
.always()) and auto-serializes data, sets headers, and handles JSON parsing
via config options. fetch() is native, returns a real Promise, but requires
manual JSON parsing (.json()) and doesn't reject on HTTP error status codes
(only on network failure) -- a common gotcha.

Example:
    $.ajax({ url: '/api/data', method: 'GET', dataType: 'json' })
      .done(data => console.log(data))
      .fail(err => console.error(err));

    fetch('/api/data')
      .then(res => res.json())
      .then(data => console.log(data))
      .catch(err => console.error(err));


7. Deferred objects / Promises

jQuery's $.Deferred() predates the ES6 Promise spec and isn't fully
spec-compliant (e.g., its .then() doesn't always return a new promise
pre-3.0). Key methods: .resolve()/.reject() to settle it, .done()/.fail()/
.always() to attach callbacks, $.when() to combine multiple deferreds
(like Promise.all).


8. .detach() vs .remove() vs .empty()

- .remove() -- removes elements from the DOM AND strips jQuery data/event
  handlers.
- .detach() -- removes from the DOM but KEEPS data/event handlers attached,
  so you can reinsert it later with handlers intact (useful for
  re-ordering heavy elements without rebinding events).
- .empty() -- removes all CHILD elements/content but keeps the element
  itself in the DOM.


9. $.fn.extend -- writing a jQuery plugin

Tests whether they understand jQuery's prototype ($.fn is
jQuery.prototype). A plugin adds a method to every jQuery object:

Example:
    $.fn.highlight = function(color) {
      return this.css('background-color', color); // return `this` for chainability
    };
    $('.warning').highlight('yellow');


10. Why has jQuery usage declined, and when would you still choose it?

Good closer question to gauge judgment, not just trivia. Native DOM APIs
now cover most of what jQuery offered; SPA frameworks (React/Vue) own DOM
updates directly, making jQuery's imperative manipulation conflict with
their virtual DOM model. Still reasonable for: legacy codebases,
WordPress/plugin ecosystems, or quick scripts needing broad legacy-browser
AJAX/animation support without a build step.
